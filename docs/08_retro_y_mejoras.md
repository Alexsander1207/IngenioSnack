# 08. Retrospectiva XP y mejoras futuras

## 1. Retrospectiva de la practica

La practica permitio aplicar la metodologia XP en la etapa inicial de un proyecto realista. A partir de una conversacion con el cliente, se identificaron necesidades, restricciones, historias de usuario, criterios de aceptacion, estimaciones y tarjetas CRC.

## 2. Que salio bien

| Aspecto | Resultado |
|---|---|
| Comunicacion con el cliente | Se extrajeron necesidades claras desde la conversacion del Sr. Julio. |
| Simplicidad | Se evito agregar funcionalidades innecesarias como pagos digitales o delivery. |
| Priorizacion | La Iteracion 1 se cerro exactamente en 20 puntos. |
| Diseno simple | Las tarjetas CRC se enfocaron en el flujo principal de pedir y recoger. |
| Trazabilidad | Se relacionaron requerimientos, historias, backlog y pruebas de aceptacion. |

## 3. Que se podria mejorar

| Aspecto | Mejora propuesta |
|---|---|
| Identificacion del estudiante | Validar en una futura iteracion si conviene usar solo codigo universitario o tambien correo institucional. |
| Gestion de pedidos | Crear una vista mas completa para que el Sr. Julio marque pedidos como listos o entregados. |
| Fidelidad | Implementar el beneficio de cafe americano despues de validar el flujo de pedidos. |
| Reportes | Agregar resumen de productos mas vendidos en dias especificos. |
| Experiencia de usuario | Crear prototipos visuales en Figma o Canva. |

## 4. Historias sugeridas para futuras iteraciones

| ID | Historia futura | Motivo |
|---|---|---|
| HU-06 | Pago contra entrega registrado | Cerrar administrativamente la venta. |
| HU-07 | Programa de fidelidad | Premiar estudiantes frecuentes. |
| HU-08 | Productos mas vendidos | Ayudar al Sr. Julio a prepararse para dias de alta demanda. |
| HU-09 | Lista de pedidos pendientes | Mejorar la organizacion de atencion. |
| HU-10 | Notificacion de pedido listo | Reducir consultas manuales al mostrador. |
| HU-11 | Prototipo visual del flujo movil | Validar facilidad de uso con estudiantes. |

## 5. Riesgos identificados

| Riesgo | Impacto | Mitigacion |
|---|---|---|
| El Sr. Julio olvida actualizar disponibilidad | Alto | Vista simple con botones grandes para activar/desactivar productos. |
| Estudiantes hacen pedidos y no recogen | Medio | En una futura iteracion, controlar historial de pedidos no recogidos. |
| Muchos estudiantes piden al mismo tiempo | Medio | Ordenar pedidos por hora de registro. |
| Ambiguedad en beneficios | Medio | Documentar reglas exactas del cafe gratis. |
| Falta de internet en algunos momentos | Medio | Mantener interfaz ligera y de carga rapida. |

## 6. Conclusiones

La primera iteracion debe concentrarse en reducir la fila mediante pedidos anticipados y actualizacion rapida del menu. Las funciones de fidelidad, reportes y mejoras administrativas son valiosas, pero se deben implementar despues de validar que el flujo principal funciona correctamente.

Este enfoque respeta los valores de XP: comunicacion, simplicidad, retroalimentacion y entrega incremental.
